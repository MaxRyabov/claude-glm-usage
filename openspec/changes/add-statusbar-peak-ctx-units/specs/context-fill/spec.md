# Spec Delta

## Purpose

Заполнение контекста активной сессии относительно окна модели — сегмент «ctx 38%»
в статус-баре и показ на дашборде, с порогом предупреждения у автосжатия.

## ADDED Requirements

### Requirement: Окно контекста определяется по модели сессии
Расширение ДОЛЖНО (SHALL) определять окно контекста по имени модели активной сессии: суффикс окна `[1m]` в имени любой модели поднимает окно до 1 000 000 токенов; модель glm без суффикса — 200 000 токенов; модели claude без суффикса — по встроенной таблице окон Claude Code; неизвестная модель — 200 000. Переменная `CLAUDE_CODE_MAX_CONTEXT_TOKENS` переопределяет окно только для моделей, не входящих в таблицу claude.

#### Scenario: glm без суффикса получает окно 200k
- **WHEN** активная сессия работает на модели `glm-5.3`
- **THEN** окно контекста — 200 000 токенов

#### Scenario: Суффикс [1m] поднимает окно до 1M
- **WHEN** активная сессия работает на модели `glm-5.3[1m]`
- **THEN** окно контекста — 1 000 000 токенов

#### Scenario: Суффикс [1m] у модели claude тоже поднимает окно
- **WHEN** активная сессия оригинального Claude Code работает на модели claude-sonnet
  с суффиксом `[1m]`
- **THEN** окно контекста — 1 000 000 токенов, а не значение таблицы без суффикса

#### Scenario: claude-модель берётся из встроенной таблицы
- **WHEN** активная сессия работает на модели `claude-sonnet-*`
- **THEN** окно контекста — из встроенной таблицы Claude Code

#### Scenario: Короткое имя модели claude берётся из таблицы
- **WHEN** активная сессия работает на модели с коротким именем sonnet или haiku
- **THEN** окно контекста берётся из встроенной таблицы, а не из дефолта для неизвестных

#### Scenario: Override действует только для не-claude моделей
- **WHEN** задана `CLAUDE_CODE_MAX_CONTEXT_TOKENS=400000`, а активная сессия работает
  на неизвестной модели
- **THEN** окно контекста — 400 000 токенов
- **WHEN** та же переменная задана при модели из таблицы claude
- **THEN** окно берётся из таблицы, а не из переменной

### Requirement: Заполнение считается по последнему ходу активной сессии
Расширение ДОЛЖНО (SHALL) считать заполнение контекста как сумму input, cache_read
и cache_creation последнего хода активной сессии — последний ход несёт весь
накопленный контекст, — и показывать долю этой суммы от окна модели в процентах.
Активной считается сессия верхнего уровня с самой поздней отметкой времени хода
среди сессий проекта текущего воркспейса; ходы субагентов в подкаталогах активной сессией не считаются.

#### Scenario: Последний ход даёт заполнение окна
- **WHEN** последний ход активной сессии несёт input 10k, cache_read 50k,
  cache_creation 5k при окне 200k
- **THEN** сегмент показывает «ctx 33%»

#### Scenario: Самая поздняя сессия проекта воркспейса выигрывает
- **WHEN** в проекте текущего воркспейса несколько сессий, а самый поздний ход — в другой сессии того же проекта
- **THEN** заполнение показывается по самой поздней сессии проекта воркспейса

#### Scenario: Чужой проект не выигрывает
- **WHEN** самый поздний ход по всем логам — в сессии другого проекта
- **THEN** заполнение показывается по самой поздней сессии проекта воркспейса, а не чужой

#### Scenario: Воркспейс без проекта скрывает сегмент
- **WHEN** текущий воркспейс не отображается ни на один проект в логах
- **THEN** сегмент контекста не показывается

#### Scenario: Без ходов сегмент не показывается
- **WHEN** ни одна сессия не содержит ходов
- **THEN** сегмент контекста не показывается

#### Scenario: Переполнение окна показывается фактическим процентом
- **WHEN** override занижает окно и сумма последнего хода превышает его
- **THEN** сегмент показывает фактическую долю («ctx 104%») со знаком ⚠, без клэмпа

### Requirement: Предупреждение появляется у порога автосжатия
Расширение ДОЛЖНО (SHALL) помечать сегмент контекста знаком ⚠, когда заполнение
достигает порога автосжатия — окна минус 20 000 токенов, — и не помечать ниже
порога, повторяя поведение виджета самого Claude Code.

#### Scenario: У порога появляется предупреждение
- **WHEN** контекст активной сессии — 185k при окне 200k
- **THEN** сегмент показан с ⚠

#### Scenario: Ниже порога предупреждения нет
- **WHEN** контекст активной сессии — 170k при окне 200k
- **THEN** сегмент показан без ⚠

### Requirement: Сегмент контекста показывается только при свежей активности
Расширение ДОЛЖНО (SHALL) показывать сегмент контекста, пока последний ход активной
сессии не старше шести часов; более старый ход сегмент скрывает до новой активности.

#### Scenario: Свежий ход держит сегмент
- **WHEN** последний ход активной сессии совершен час назад
- **THEN** сегмент контекста показан

#### Scenario: Вчерашний ход сегмент скрывает
- **WHEN** последний ход активной сессии совершен вчера
- **THEN** сегмент контекста не показывается
