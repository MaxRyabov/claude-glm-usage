# Spec Delta

## Purpose

Скорость прожигания квоты и прогноз её исчерпания в единицах провайдера: кредиты z.ai
по официальной формуле с множителями по моделям и скидкой вне пика, доллары — как
сейчас; прогноз сверяется с реальной квотой из кэша.

## ADDED Requirements

### Requirement: Скорость прожигания считается одним движком в двух единицах
Расширение ДОЛЖНО (SHALL) вычислять скорость прожигания по локальным записям JSONL скользящего окна одним движком, который отдаёт результат одновременно в кредитах z.ai и в долларах США. Выбор единицы отображения на расчёт не влияет: обе величины всегда доступны потребителям. В расчёт входят и ходы субагентов из подкаталогов subagents — без них скорость систематически занижена.

#### Scenario: Одни записи дают обе величины
- **WHEN** движок получает записи ходов за скользящее окно
- **THEN** он отдаёт скорость в кредитах в час и в долларах в час за один расчёт

#### Scenario: Единица отображения не меняет расчёт
- **WHEN** первичная единица переключается между кредитами и долларами
- **THEN** пересчитываются только показания, а не сам движок скорости

#### Scenario: Ходы субагентов входят в скорость
- **WHEN** в окне есть ходы главной сессии и ходы её субагентов на GLM-моделях
- **THEN** скорость учитывает и те, и другие записи

### Requirement: Кредиты z.ai считаются по официальной формуле с множителями модели
Расширение ДОЛЖНО (SHALL) считать кредиты z.ai каждого хода как `(input × M_in + cache_read × M_cache + output × M_out) / 10000`, беря множители по модели хода: GLM-5.3 — 6.9 / 1.7 / 24, GLM-5.3-Flash — 2.3 / 0.56 / 8; слагаемого cache_creation в формуле нет — z.ai учитывает записи кэша в input.

#### Scenario: Ход GLM-5.3 считается по базовым множителям
- **WHEN** ход модели GLM-5.3 несёт input 1000, cache_read 1000, output 100
- **THEN** кредиты хода составляют 1.1

#### Scenario: Ход Flash считается по тройной скидке
- **WHEN** тот же объём токенов несёт ход модели GLM-5.3-Flash
- **THEN** кредиты хода составляют 0.366

#### Scenario: Cache creation не прибавляет кредитов
- **WHEN** два хода GLM-5.3 совпадают по input, cache_read и output, но различаются
  по cache_creation
- **THEN** кредиты обоих ходов равны

### Requirement: Кредиты начисляются только ходам GLM-моделей
Расширение ДОЛЖНО (SHALL) включать в кредитные агрегаты только ходы GLM-моделей: ходы claude-* и неизвестных моделей не начисляют кредитов. Запись JSONL не несёт провайдера, а история может быть смешанной — кредитная модель z.ai не приписывает Anthropic-токены кредитному тарифу.

#### Scenario: Ход модели claude не прибавляет кредитов
- **WHEN** в окне расчёта ход glm-5.3 (кредиты 1.1) и ход claude-opus-5-5
- **THEN** кредитная сумма окна — 1.1: ход claude-модели в кредиты не входит

### Requirement: Вне пика кредиты делятся пополам
Расширение ДОЛЖНО (SHALL) применять к кредиту каждого хода коэффициент 0.5, когда
отметка времени хода попадает вне пик-часов z.ai, и базовый коэффициент — внутри
пика, так что сессия, пересекающая границу пика, оценивается почасово по обеим
ставкам.

#### Scenario: Одинаковый ход в пике и вне пика стоит вдвое по-разному
- **WHEN** два одинаковых хода GLM-5.3 совершены в будний день в 07:00 UTC и в 12:00 UTC
- **THEN** кредит второго хода равен половине кредита первого

#### Scenario: Выходной весь день вне пика
- **WHEN** ход совершён в субботу 07:00 UTC
- **THEN** к его кредиту применён коэффициент 0.5

### Requirement: Прогноз исчерпания сверяется с реальной квотой
Расширение ДОЛЖНО (SHALL) при живых данных квоты z.ai с абсолютными величинами считать прогноз исчерпания 5-часового окна из величин credits5h и скорости прожигания в кредитах, ограничивая горизонт временем сброса (reset5hAt); если окно не исчерпается до сброса — сообщать именно это. При нулевой скорости (в окне нет ходов) прогноз исчерпания не строится. Без абсолютных величин прогноз оценивается из утилизации и расхода за окно, как раньше.

#### Scenario: Запас перекрывает скорость до сброса
- **WHEN** израсходовано 5000 из 28000 кредитов, скорость 4000 кредитов в час,
  до сброса 2 часа
- **THEN** прогноз сообщает, что окно не исчерпается до сброса

#### Scenario: Скорость ведёт к исчерпанию до сброса
- **WHEN** остаётся 1000 кредитов, скорость 4000 кредитов в час, до сброса 2 часа
- **THEN** прогноз сообщает исчерпание примерно через 15 минут

#### Scenario: Токенный тариф оценивается по утилизации
- **WHEN** квота z.ai не сообщает абсолютных величин, а только проценты
- **THEN** прогноз исчерпания оценивается из утилизации и расхода за окно прежним
  способом

#### Scenario: Нулевая скорость не даёт прогноза
- **WHEN** окно скорости не содержит ходов, а квота z.ai живая и с величинами
- **THEN** прогноз исчерпания не показывается

### Requirement: Прогноз не опирается на неживые данные квоты
Расширение ДОЛЖНО (SHALL) использовать величины кредитов из кэша в прогнозе только
при живых данных об ограничениях и не строить прогноз исчерпания по протухшим
величинам — в согласии с требованием «Утилизация показывается только при живых
данных об ограничениях» спеки zai-quota-parsing.

#### Scenario: Протухший кэш не даёт прогноза исчерпания
- **WHEN** данные квоты с величинами кредитов показаны как протухшие
- **THEN** прогноз не утверждает исчерпание из этих величин и показывается без него
