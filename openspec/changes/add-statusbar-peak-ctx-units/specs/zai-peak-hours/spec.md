# Spec Delta

## Purpose

Определение пик-часов z.ai — времени, когда кредиты стоят вдвое дороже, — и их показ
в статус-баре и на дашборде: локально, без обращений к API, только для провайдера z-ai.

## ADDED Requirements

### Requirement: Пик z.ai определяется локально по системным часам
Расширение ДОЛЖНО (SHALL) определять попадание текущего момента в пик-часы z.ai
исключительно локально: пик — интервал с 06:00 до 10:00 UTC каждого дня с понедельника
по пятницу. Классификация ведётся по UTC, поэтому один и тот же момент одинаково
классифицируется на любой машине; переход на летнее время определение не меняет.

#### Scenario: Будний день внутри окна — пик
- **WHEN** текущий момент соответствует понедельнику 06:30 UTC
- **THEN** момент классифицируется как пик

#### Scenario: Будний день вне окна — не пик
- **WHEN** текущий момент соответствует понедельнику 11:00 UTC
- **THEN** момент классифицируется как время вне пика

#### Scenario: Выходной внутри оконных часов — не пик
- **WHEN** текущий момент соответствует субботе или воскресенью 07:00 UTC
- **THEN** момент классифицируется как время вне пика

#### Scenario: Классификация не зависит от пояса машины
- **WHEN** один и тот же момент оценивается на машинах с поясами UTC+3 и UTC−5
- **THEN** обе машины сообщают одинаковое попадание в пик

### Requirement: Границы пика показываются в локальном часовом поясе
Расширение ДОЛЖНО (SHALL) строить подсказку о пике в локальном часовом поясе ПК
стандартными API, без зафиксированного в коде смещения: внутри пика — локальное время
окончания («пик до 13:00»), вне пика — границы окна в локальном времени с указанием
текущего смещения пояса («пик 09:00–13:00 (UTC+3)»). Смещение летнего времени
учитывается автоматически.

#### Scenario: Внутри пика подсказка называет время окончания
- **WHEN** текущий момент — 12:13 локального времени в поясе UTC+3, будний день
- **THEN** подсказка содержит локальное время окончания окна, например «пик до 13:00»

#### Scenario: Вне пика подсказка называет границы окна в местном времени
- **WHEN** текущий момент — вечер буднего дня в поясе UTC+3
- **THEN** подсказка называет границы окна «09:00–13:00 (UTC+3)»

#### Scenario: Тот же момент в другом поясе даёт свои границы
- **WHEN** тот же момент оценивается машиной в поясе UTC+8
- **THEN** подсказка называет границы «14:00–18:00 (UTC+8)» — то же окно UTC в местном
  исчислении

### Requirement: Индикатор пика показывается только для провайдера z-ai
Расширение ДОЛЖНО (SHALL) показывать метку ⚡ рядом с окнами квоты в статус-баре и на дашборде тогда и только тогда, когда провайдер — z-ai и текущий момент в пике. Для остальных провайдеров метка не показывается никогда: пикового тарифа у Anthropic нет. Метка не зависит от данных квоты и видна при выключенном опросе API. В деградационных состояниях без обычных сегментов (нет учётных данных, нет данных, отказ входа) метка не показывается.

#### Scenario: z-ai в пике показывает метку
- **WHEN** провайдер — z-ai, текущий момент — будний день 07:00 UTC
- **THEN** метка ⚡ показана в статус-баре и на дашборде рядом с окнами квоты

#### Scenario: z-ai вне пика метку не показывает
- **WHEN** провайдер — z-ai, текущий момент — будний день 12:00 UTC
- **THEN** метка ⚡ не показывается

#### Scenario: Anthropic метку не показывает никогда
- **WHEN** провайдер — claude-ai, текущий момент — будний день 07:00 UTC
- **THEN** метка ⚡ не показывается ни в статус-баре, ни на дашборде

#### Scenario: Пик виден и без данных квоты
- **WHEN** провайдер — z-ai, текущий момент — пик, опрос API отключён (local-only)
- **THEN** метка ⚡ показана рядом с имеющимися сегментами статус-бара

#### Scenario: Деградационное состояние не показывает метку
- **WHEN** провайдер — z-ai, момент — пик, показан режим «нет учётных данных»
- **THEN** метка ⚡ не показывается, деградационный показ не меняется

### Requirement: Индикатор пика не порождает обращений к API
Расширение ДОЛЖНО (SHALL) обновлять индикатор пика в существующих циклах перерисовки
статус-бара и дашборда, не добавляя обращений к провайдеру: правило «не чаще одного
запроса в пять минут на холостом ходу» не затрагивается. Метка обновляется в существующих циклах перерисовки (раз в минуту); отдельный таймер не заводится — момент входа в пик отражается с задержкой до одного цикла.

#### Scenario: Перерисовка по таймеру не обращается к провайдеру
- **WHEN** статус-бар перерисовывается таймером холостого хода, а текущий момент — пик
- **THEN** определение и показ пика не добавляют запросов сверх действующего бюджета
  опроса
