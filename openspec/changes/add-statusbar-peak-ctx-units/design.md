# Design

## Context

`prediction.ts` сегодня считает скорость и прогноз только в долларах; `statusBar.ts`
собирает метку из окон квоты и проектной стоимости в USD; провайдер уже известен
(`providerType`), а кэш квоты несёт `credits5h`/`credits7d` (необязательные,
`QuotaAmounts`) и `reset5hAt` — абсолютные Unix-секунды. Все потребители данных ходят
через `DataManager` → `ClaudeUsageData`, вебвью получает всё одним сообщением `update`,
а снапшот холодного старта и валидатор снапшота переживают необязательные поля. Чтение
JSONL — инкрементальный `entryCache` с дедупом по `requestId`/`message.id`; обход
`discoverFiles` сегодня нерекурсивный — субагенты из подкаталогов в данные не попадают (замер на живых логах: 294 вложенных файла против 191 верхнего уровня; по справочнику субагенты — 59% расхода кредитов), поэтому изменение расширяет обход на подкаталоги `<сессия>/subagents/*.jsonl`; файлы верхнего уровня остаются единственными кандидатами в активную сессию и счёт сессий. Сигнатура кэша обхода (dirSig) дополняется mtime сессионных каталогов: иначе новый файл в уже существующем subagents/ не меняет сигнатуру, и walkCache молча отдаёт прежний список без свежих субагентских ходов.

Мотивация изменения — в `proposal.md` (Why); требования — в дельтах спек.

## Goals / Non-Goals

**Goals:**
- Один движок скорости с двумя единицами; кредиты z.ai — по официальной формуле,
  с пик/офпик-коэффициентом по отметке времени каждого хода.
- Пик-часы, контекст и единицы доезжают до статус-бара и дашборда через существующий
  поток `ClaudeUsageData` → `onDidUpdate` → `update`, без новых сообщений и без
  обращений к API.
- Нулевая миграция: новая настройка с дефолтом `auto`, снапшот и схема кэша не меняются.

**Non-Goals:**
- Метрики «Здоровья связки» (CHR, медианный контекст, доля субагентов) — изменение 2.
- Состав префикса сессии, метки 429, бюджет прогона в кредитах — изменение 3.
- Учёт `TIME_LIMIT` (месячный лимит MCP) и новых эндпоинтов z.ai.
- Тепловая карта и «Avg cost by hour» остаются в долларах — перевод их в кредиты относится к изменению 2 («Здоровье связки»).
- Настройка окна пика пользователем: окно фиксировано тарифом z.ai.

## Decisions

### D1. Пик-часы — чистый модуль `src/data/peakHours.ts`, UTC-инвариант
`peakStatus(now, providerType)` возвращает `{ active, windowStartLocal, windowEndLocal }`.
Окно задано константой в UTC: будни 06:00 ≤ t < 10:00 (14:00–18:00 SGT). Попадание
считается по UTC-компонентам даты, локальный показ — `Intl.DateTimeFormat` с текущим
смещением пояса (`timeZoneName` для «(UTC+3)»). «Сейчас» инжектится параметром —
тестируемость без часов. Альтернатива — хранить окно в SGT и конвертировать — отвергнута:
SGT без летнего времени, но лишняя конвертация даёт те же UTC-часы с большим числом
мест, где можно ошибиться. Метка попадает в `ClaudeUsageData.peak` при каждом
`runRefresh` и на каждом тике перерисовки статус-бара пересчитывается на лету (дёшево),
поэтому тултип «пик до 13:00» не устаревает между обновлениями.

### D2. Кредиты — функция от записи, множители по модели с Flash-веткой
`creditsForEntry(entry, peakActive)` в новом модуле рядом с `pricing.ts`
(`src/data/credits.ts`): `(input × M_in + cache_read × M_cache + output × M_out) / 10000`,
`cache_creation` игнорируется. Множители: имя модели содержит `flash` (регистр
не важен) → 2.3 / 0.56 / 8, иначе — 6.9 / 1.7 / 24. Кредиты начисляются только записям GLM-моделей — имя содержит `glm` или `flash` (регистр не важен); записи `claude-*` и неизвестных моделей в кредитные агрегаты не входят: запись JSONL не несёт провайдера, а история смешанная (замер за 7 дней: 43736 записей `glm-5.3` и 3023 `claude-opus-5-5`), и прежняя идея считать `claude-*` базовыми множителями приписывала бы Anthropic-токены кредитному тарифу z.ai — отвергнута ревью. Цена редких z.ai-ходов под маппингами `claude-*` теряется — принято осознанно: расхождение видно в строке сверки (D7). Бесплатные flash-модели старых линеек (glm-4.7-flash) попадают под фильтр и начисляют кредиты — устойчивое локальное завышение против квоты, видимое той же сверкой; риск принят.
Альтернатива — таблица по каждому имени GLM — отвергнута: справочник задаёт ровно два
тарифных класса, а дробление по именам умножало бы места рассинхрона с реальностью.
Коэффициент 0.5 вне пика применяется по `timestamp` записи (`peakStatus` от метки
времени хода), не по текущему моменту — сессия, пересёкшая 10:00 UTC, оплачивается
по обеим ставкам. Одна и та же функция используется агрегаторами окна/дня/проекта
и движком скорости, чтобы «§2.8k» везде означало одно и то же число.

### D3. `prediction.ts` — один проход, два результата
`computePrediction` расширяется: читает те же записи окна 30 минут, но рядом с USD
копит кредиты (`creditsForEntry`), и отдаёт `burnRateCreditsPerHour` рядом с существующим `currentBurnRate` (USD, поле сохраняется — на него смотрят дашборд
и тесты). Прогноз исчерпания для z-ai при живой квоте с величинами строится из
`credits5h.remaining` (или `total − used`, если `remaining` отсутствует — помня, что
upstream округляет) и `burnRateCreditsPerHour`, горизонт капится `resetIn5h`;
`remaining / burn > resetIn5h` → поле исчерпания пусто с комментарием «не исчерпается
до сброса». Без величин — прежний вывод ёмкости `spend5h / utilization5h`, где для
z-ai `spend5h` — кредиты окна. «Живость» определяется существующим `actsOnRateData` — он строже `showsRateData` ровно на состояние `stale`, как требует дельта: протухший остаток не даёт кредитного прогноза
(см. требование «Прогноз не опирается на неживые данные квоты»). Экстраполяция ведётся одной ставкой окна: у границы пика ошибка достигает двух раз в обе стороны — на выходе из пика прогноз пессимистичен, а на входе, когда окно целиком офпиковое, а следующий час дороже, — оптимистичен; кусочная экстраполяция по участкам пика/офпика признана избыточной, ограничение фиксируется в docs/DATA.md (задача 5.3).

### D4. Контекст — `src/data/contextFill.ts` поверх `entryCache`
Окно модели: `resolveContextWindow(model, env)` — суффикс `[1m]` проверяется первым для любой модели, включая claude (селектор 1M-окна в самом Claude Code) → 1M; `glm-*` → 200k; `claude-*` → встроенная таблица (стартовый набор — актуальные окна Claude Code, включая короткие имена sonnet/haiku/opus); прочее → 200k. `CLAUDE_CODE_MAX_CONTEXT_TOKENS` (приведённая к числу) переопределяет
только не-claude модели — так ведёт себя сам Claude Code. Переменная читается
существующим `readClaudeEnvVar` (process.env → `~/.claude/settings.json` →
`settings.local.json`) — env расширения не видит env Claude Code.
Активная сессия: новый запрос к `entryCache` — по кэшированным записям файлов найти
файл верхнего уровня проекта текущего воркспейса (маппинг пути воркспейса на проектную папку — существующий из `projectCost.ts`; модель и usage последнего хода достаточны, путь не нужен). `UsageEntry` не несёт источник, поэтому в `entryCache`
добавляется `findActiveSession(freshnessMs)` — обход in-memory кэша O(файлов) — в кэше файла инкрементально поддерживается последняя не-synthetic запись (отметка времени, модель, usage) — она же заменяет maxTimestamp; старый кэш без этого поля получает его разовым проходом при первой загрузке, после чего поиск самой поздней записи не перебирает все записи на каждом тике перерисовки; чтения с диска нет. Синтетические записи `<synthetic>` при выборе последнего хода пропускаются. Заполнение = `input + cache_read + cache_creation` последнего
хода; порог ⚠ — `window − 20000`. Свежесть — 6 часов (чуть больше 5-часового окна
квоты): сегмент описывает текущую работу, а не вчерашнюю. Результат кладётся
в `ClaudeUsageData.context` и живёт одним refresh-циклом со всеми остальными данными.

### D5. Единицы — резолвер в `config.ts`, формат кредитов со знаком §
`resolvePrimaryUnit(providerType, setting)`: `auto` → z-ai ? credits : usd; `credits`
для не-z-ai деградирует к usd (кредитная модель определена только для z-ai); `usd` —
как задан. Формат: `formatCredits(n)` — до 9 999 целым числом, дальше сокращение
`§2.8k`/`§1.2M` в стиле существующего `formatTokens`. Знак `§` выбран в макетах плана:
односимвольный, не путается с `$`, есть в моноширинных шрифках статус-бара. Проектная
стоимость и дневной расход агрегируются в обеих единицах одним проходом (D2), так что
переключение единицы меняет только отрисовку. Вторая единица (USD) для z-ai обязана считать по актуальным ценам: `MODEL_PRICING` пополняется glm-5.3 и glm-5.3-flash по официальному прайсу z.ai (задача 1.5) — сегодня эти имена матчатся префиксом на устаревшую цену glm-5 (1.00 / 3.20 / 0.20 за MTok), и долларовая половина показа врала бы.

### D6. Статус-бар: сегменты через «·», состав не ломаем
Метка: `🤖 5h:12% 7d:3% [⚡] · ctx 38% · my-app:§2.8k`. Сегмент пика — сразу после окон
квоты (только z-ai в пик), сегмент контекста — перед стоимостным, стоимостной сегмент
сохраняет сегодняшнюю семантику проектной стоимости (`showProjectCost`, имя проекта
при одном корне), но отрисовывается в первичной единице. Разделитель `|` заменяется
на `·` — метка с четырьмя сегментами иначе не помещается. Режимы деградации
(`no-credentials`, `no-data`, `auth-rejected`, stale-суффикс) не меняются.

### D7. Дашборд: эволюция существующих карточек, без новой вкладки
Карточка CURRENT USAGE становится панелью «Сейчас»: к прогрессам 5h/7d добавляется
абсолютное время сброса (из `resetIn5h`/`reset5hAt`), отметка ⚡ в пике и скорость
в двух единицах и строка сверки множителей — локально насчитанные кредиты за окно квоты — от `reset5hAt` − 5 часов до текущего момента, а не скользящие часы, — против `credits5h.used` («локально §X · по квоте §Y за 5ч»), закрывающая обещанный в Risks детектор отставания тарифа; Prediction card показывает сверенный с квотой прогноз и кредитный
путь. Сообщение `update` расширяется необязательными полями `peak`, `context`,
`units` и расширенным `prediction` — валидатор снапшота v1 их принимает, бампать
версию схемы не нужно. Пик и контекст в снапшот не пишутся: пик протухает минутами,
контекст пересчитывается из `entryCache` мгновенно.

### D8. Настройка и l10n
`claudeStatus.display.primaryUnit` (`auto | credits | usd`, default `auto`) в `package.json` + описание во всех четырёх бандлах `package.nls*.json` и синхронно
в `docs/SETTINGS.md`. Новые строки интерфейса («пик до …», «ctx …», «кр/ч») — через
`vscode.l10n.t` с ключами в тех же бандлах. Смена настройки подхватывается
существующим `onDidChangeConfiguration` → перерисовка.

## Risks / Trade-offs

- [Множители формулы отстанут от тарифа z.ai] → они же сверяются с `credits5h` строкой «локально §X · по квоте §Y» в панели «Сейчас» (D7): расхождение прогноза с фактом видно на дашборде; множители
  собраны одной константой в `credits.ts` с комментарием-ссылкой на справочник.
- [Активная сессия ищется в проекте текущего воркспейса] → маппинг переиспользуется из `projectCost.ts`; воркспейс без проекта в логах не получает сегмент ctx, при параллельных окнах каждое показывает свою сессию.
- [Статус-бар переполняется на четырёх сегментах] → сегменты пика и контекста
  появляются только при наличии данных; имя проекта уже усечено до 12 символов;
  критная сборка проверяется тестом `buildLabel`.
- [Обход записей ради кредитов удлиняет агрегацию] → кредиты копятся в тех же
  проходах, что и доллары (`readAllUsage`, проектная стоимость, окно скорости),
  отдельного прохода нет; O(записей) не меняется.
- [`remaining` у z.ai округлён] → сверка прогноза использует `remaining` как есть
  (консервативно к меньшему остатку), при отсутствии — `total − used`, как требует
  спека zai-quota-parsing не пересчитывать отданное.
- [Субагенты и MCP-вызовы расширяют расхождение локального счёта с квотой] → субагентские файлы входят в обход (замер до/после в задаче 1.4), а MCP-вызовы (server_tool_use) в формуле не представлены — сверка сходится с точностью до MCP; ограничение фиксируется в docs/DATA.md.
- [z.ai-ходы под маппингами `claude-*` выпадают из кредитного счёта] → доля мала по живым логам, расхождение видно в строке сверки; пересмотр фильтра — при накоплении статистики.

## Migration Plan

1. Настройка новая, дефолт `auto` — поведение claude-ai и провайдеров без квоты
   неотличимо от прежнего; отката не требуется.
2. Снапшот и кэш квоты не меняются (необязательные поля); старые окна расширения
   читают новые поля молча.
3. Откат — реверт PR: статус-бар возвращается к долларовому виду, данные
   не затрагиваются.

  на дневной расход без имени, как в макете «$0.42». Решил в пользу сохранения
  текущей семантики; смена — одна строка в `buildLabel`.
- Финальный вид панели «Сейчас» (порядок и группировка) уточняется при реализации
  по навыку dataviz; структура данных (`peak`, `context`, `units`, `prediction`)
  зафиксирована здесь.
