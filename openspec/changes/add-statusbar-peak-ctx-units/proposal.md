# Proposal: add-statusbar-peak-ctx-units

## Why

Связка Claude Code + GLM живёт в кредитах z.ai, а расширение говорит только процентами
и долларами: скорость прожигания и прогноз исчерпания в `prediction.ts` считаются
исключительно в USD, пик-часы z.ai — когда кредиты стоят вдвое дороже — нигде не видны,
а заполнение контекста активной сессии, главный предиктор утечки квоты по справочнику,
не показывается вовсе. Справочник квоты (формулы кредитов, множители по моделям,
пик-часы, показатели контроля) уже зафиксирован, а слитый PR #15 принёс в кэш реальные
величины квоты (`credits5h`/`credits7d`, `reset5hAt` с инвалидацией по отпечатку ключа) —
прогноз теперь можно и считать в кредитах, и сверять с действительностью.

Это первое из трёх независимо поставляемых изменений согласованного плана; за ним теми
же циклами идут «Здоровье связки» и «Гигиена сессии».

## What Changes

| ID | Фича |
|----|------|
| SB-1 | Индикатор пик-часов ⚡ в статус-баре и дашборде |
| SB-2 | Прогноз расхода в кредитах z.ai — доработка существующего `src/data/prediction.ts` |
| SB-3 | Заполнение контекста активной сессии «ctx 38%» в статус-баре |
| SB-4 | Скорость прожигания с настраиваемой единицей (кредиты/доллары) |

- **SB-1** → Метка ⚡ рядом с окнами квоты в статус-баре и на дашборде, пока текущий
  момент попадает в пик z.ai. Окно хранится в UTC — будни 06:00–10:00 (= 14:00–18:00
  SGT, 09:00–13:00 МСК), отображение и подсказка («пик до 13:00», «пик 09:00–13:00
  (UTC+3)») — в локальном часовом поясе ПК через стандартные API, без хардкода МСК;
  переход на летнее время обрабатывается ими же. Только для провайдера z-ai: у Anthropic
  пикового тарифа нет, метка скрыта. Считается локально из системных часов, **без новых
  вызовов API** — правило «не чаще одного запроса в 5 минут на холостом ходу»
  не затрагивается.
- **SB-2** → Один движок скорости в `prediction.ts` с двумя единицами. Для z-ai кредиты
  считаются по официальной формуле `(input × 6.9 + cache_read × 1.7 + output × 24) / 10000`
  для GLM-5.3; для GLM-5.3-Flash множители 2.3 / 0.56 / 8; вне пика — ×0.5; кредиты начисляются только ходам GLM-моделей — смешанная история не приписывает Anthropic-токены z.ai; в расчёт входят и ходы субагентов;
  `cache_creation` z.ai не отчитывает (он уже учтён в `input`). Для claude-ai всё
  остаётся в долларах, как сейчас. Прогноз исчерпания сверяется с реальной квотой
  из кэша: `credits5h`/`credits7d` дают фактический расход и лимит, `reset5hAt` —
  горизонт окна.
- **SB-3** → Сегмент «ctx 38%» в статус-баре (и на дашборде): заполнение контекста
  активной сессии проекта текущего воркспейса относительно окна модели. Окно определяется по модели: glm без
  суффикса — 200k, суффикс `[1m]` — 1M, claude-модели — встроенная таблица,
  `CLAUDE_CODE_MAX_CONTEXT_TOKENS` переопределяет окно для не-claude моделей. Порог ⚠ —
  при приближении к автосжатию (окно − 20k), как в самом Claude Code.
- **SB-4** → Новая настройка `claudeStatus.display.primaryUnit`: `auto | credits | usd`;
  `auto` выбирает кредиты для z-ai и доллары для claude-ai. Влияет на всю стоимостную запись: сегмент проектной стоимости, окна квоты в режиме displayMode: cost, стоимостной тултип, единицу скорости прожигания и показания дашборда.
- **Парсинг** → Обход JSONL расширяется на подкаталоги субагентов `<сессия>/subagents/*.jsonl`: без них скорость прожигания занижена примерно вдвое (субагенты — большая доля расхода кредитов по справочнику); число сессий и активная сессия остаются на файлах верхнего уровня, стоимостные агрегаты растут — это исправление давнего занижения. Долларовые агрегаты вырастут у всех провайдеров: субагентские файлы у Anthropic пишутся так же — скачок осознан и описывается в CHANGELOG.
- Обратная совместимость с Anthropic сохранена по всем четырём фичам: у claude-ai
  единица остаётся $, пик-часы и кредиты активны только для z-ai; определение
  провайдера — существующее (`ANTHROPIC_BASE_URL` → `claudeStatus.claudeProvider`).
- **BREAKING**: нет. Схема кэша и протокол сообщений вебвью расширяются только
  необязательными полями.

## Capabilities

### New Capabilities
- `zai-peak-hours`: определение пик-часов z.ai локально из системных часов и их показ
  в статус-баре и на дашборде — окно в UTC, отображение в локальном поясе, только
  для провайдера z-ai, без обращений к API.
- `usage-prediction`: скорость прожигания и прогноз исчерпания квоты в выбираемой
  единице — единый движок, кредитная модель z.ai с множителями по моделям и скидкой
  вне пика, долларовая модель claude-ai, сверка прогноза с реальной квотой из кэша.
- `context-fill`: заполнение контекста активной сессии — окно по модели с override,
  доля заполнения и порог предупреждения об автосжатии.
- `display-units`: выбор первичной единицы отображения расходов (auto / credits / usd)
  и её применение в статус-баре и на дашборде.

## Impact

- **Затронутые спеки**: `zai-peak-hours`, `usage-prediction`, `context-fill`,
  `display-units` — все новые.
- **Затронутый код**: `src/data/prediction.ts` (ядро SB-2), `src/data/entryCache.ts` (обход субагентов, инкрементальный maxTimestamp), `src/data/pricing.ts` (цены glm-5.3), новые `src/data/peakHours.ts`
  и `src/data/contextFill.ts`, `src/data/credits.ts`, `src/data/dataManager.ts` (прокидывание новых данных),
  `src/statusBar.ts` (сегменты ⚡ и ctx, единица), `src/webview/panel.ts` и HTML-шаблон
  дашборда (панель «Сейчас»: сброс 5ч-окна, отметка пика, скорость, прогноз),
  `src/config.ts`, `package.json` + бандлы `package.nls*.json` (настройка, строки),
  `docs/SETTINGS.md`, `docs/DATA.md`, `docs/features/01-statusbar.md`, `docs/features/04-prediction.md`,
  `CHANGELOG.md` (`[Unreleased]`).
- **Новая настройка**: `claudeStatus.display.primaryUnit` (`auto | credits | usd`,
  default `auto`) — описывается в `docs/SETTINGS.md` синхронно с `package.json`.
- **Бюджет API-вызовов**: без изменений — пик-часы, контекст и кредиты считаются из
  локальных JSONL, системных часов и уже существующего кэша квоты.
- **Поверхность регрессии Anthropic**: формат статус-бара и протокол вебвью общие для
  всех провайдеров; изменения в них сохраняют текущие режимы деградации для claude-ai неизменными; долларовые агрегаты claude-ai вырастают за счёт субагентов — осознанное исправление занижения, отражаемое в CHANGELOG и фикстурах тестов (поведение сегментов покрывается тестами `buildLabel`/`panel`).
- **Вне объёма**: вкладка «Здоровье связки» (изменение 2), состав префикса сессии,
  метки 429 и бюджет прогона в кредитах (изменение 3), месячный лимит MCP.
