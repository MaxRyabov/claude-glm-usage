## Why

`fetchRateLimitData` не проверяет статус ответа Anthropic и сразу читает заголовки
`anthropic-ratelimit-unified-*`. Если их нет — протухший OAuth-токен (проверено пробой:
401 `authentication_error`, заголовков ограничений нет) или сбой сервера, — парсер собирает
из умолчаний «0 % использовано / allowed», и это уходит в кэш с `dataSource: 'api'` на весь
TTL. Пользователь с мёртвым токеном видит картину исправного простаивающего аккаунта
(issue #8). Для z.ai тот же дефект закрыт в 1.2.0; путь Anthropic остался асимметричным,
потому что спека того изменения обещала его не трогать.

## What Changes

- Истёкший по `expiresAt` токен в API не отправляется. Показывается кэш или режим затрат
  с пометкой «токен истёк — запустите Claude Code», без красного и без паузы. На macOS
  истёкший файл больше не заслоняет свежий токен в Keychain.
- Обнаружение отказа в `fetchRateLimitData`: 401 — отвергнутый вход, 403 — отказ в доступе
  (оба дают паузу на TTL); 5xx — повторяемый сбой; ответ без единых заголовков ограничений —
  дрейф формата. Ответ с заголовками разбирается как раньше, в том числе 429 с `denied`.
- Ни одна неудача не даёт автоматических запросов к API чаще раза в 5 минут при любой
  настройке TTL: отказ и дрейф формата — пауза на `max(TTL, 5 мин)`, сеть и 5xx — повтор
  не раньше чем через 5 минут. Ручное обновление паузу обходит, успешный опрос соседнего
  окна её снимает.
- «Not logged in» показывается только при отсутствии учётных данных, а не при любом сбое
  без кэша и не у Bedrock или API-ключа без затрат.
- Подсказки ветвятся по провайдеру и причине: `🤖 Login rejected` + `claude auth login` для
  401, нейтральное `🤖 Access refused` для 403, прежний совет про `ANTHROPIC_AUTH_TOKEN`
  для z.ai, оба пути входа при неопределённом провайдере. Команда `claude login`, которой в Claude Code нет, убрана из подсказок и README.
- Утилизация из старого кэша больше не попадает в дашборд, прогноз, уведомления о порогах
  и снимок при старте, когда живых данных об ограничениях нет.
- Вне объёма: показ причины дрейфа формата — отдельный issue.
- Требования основной спеки о подавлении повторов и об отличии отказа от недоступности
  обновлены; требование «Путь ограничений Anthropic не затрагивается» переименовано
  и переформулировано.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `zai-quota-parsing`: RENAMED + MODIFIED «Путь ограничений Anthropic не затрагивается» →
  «Разбор заголовков ограничений Anthropic не меняется»; MODIFIED «Частые повторы при отказе
  аутентификации не идут в API» и «Отвергнутый ключ отличим от недоступности сервиса»;
  ADDED — истёкший токен, классификация отказов Anthropic, дрейф формата, обход паузы
  и её снятие, подсказки, показ утилизации только при живых данных, сообщение без токена.
  Пробное слияние: +10, ~3, →1, в основной спеке 28 требований.

## Impact

- `src/data/apiClient.ts` — учётные данные со сроком, Keychain на macOS, классификация
  ответа, классы ошибок.
- `src/data/authBackoff.ts` — базовые классы отказов, `backoffReasonOf`, `recordedAt`.
- `src/data/pollOutcome.ts` (новый) — исходы неудачи и простоя, решение об опросе,
  `showsRateData`, состояние снимка, данные дашборда.
- `src/data/notificationDecision.ts` — `rateSignalsFor`.
- `src/data/dataManager.ts`, `src/extension.ts`, `src/statusBar.ts`, `src/webview/panel.ts`,
  `l10n/bundle.l10n.{ru,ja,zh-cn}.json`.
- Тесты: `anthropicRateLimit.test.ts` (новый набор), `pollOutcome.test.ts` (новый),
  `statusBar.test.ts`, `panel.test.ts`.
- `docs/DATA.md`, `CHANGELOG.md`, строка `claude login` в README всех языков.
- Частота запросов: при отказе и дрейфе формата — не больше одного за `max(TTL, 5 мин)`
  на окно, при истёкшем токене — ни одного, при сети и 5xx — не чаще раза в 5 минут на окно. Сетевые
  сбои без кэша сейчас повторяются каждые 60 с — это тоже исправляется.
