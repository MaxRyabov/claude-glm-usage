## MODIFIED Requirements

### Requirement: Разбор заголовков ограничений Anthropic не меняется
Расширение ДОЛЖНО (SHALL) выводить данные об ограничениях Anthropic из заголовков ответа,
когда статус ответа не 401, не 403 и не 5xx и ответ несёт хотя бы один из заголовков
`anthropic-ratelimit-unified-5h-utilization`, `anthropic-ratelimit-unified-7d-utilization`,
`anthropic-ratelimit-unified-5h-reset`, `anthropic-ratelimit-unified-7d-reset`,
`anthropic-ratelimit-unified-5h-status` (далее — единые заголовки ограничений), трактуя времена сброса как секунды эпохи Unix, и не заполнять для ответов
Anthropic специфичные для z.ai поля модели тарификации, уровня тарифа и величин кредитов.
Иной ответ данных об ограничениях не даёт.

#### Scenario: Заголовки Anthropic разбираются без изменений
- **WHEN** ответ Anthropic несёт единые заголовки пятичасовой и семидневной утилизации
  и сброса
- **THEN** сообщённые утилизации и горизонты сброса выводятся из этих заголовков, а времена
  сброса читаются как секунды эпохи Unix

#### Scenario: Тариф без семидневного заголовка не сообщает недельного окна
- **WHEN** ответ Anthropic не несёт семидневного заголовка сброса
- **THEN** недельное окно считается отсутствующим

#### Scenario: Специфичные для z.ai поля остаются пустыми
- **WHEN** данные об ограничениях получены из ответа Anthropic
- **THEN** ни модель тарификации, ни уровень тарифа, ни величины кредитов не отдаются

#### Scenario: Исчерпанный лимит с кодом 429 по-прежнему даёт denied
- **WHEN** Anthropic отвечает статусом 429 и заголовком пятичасового статуса `denied`
- **THEN** статус лимита сообщается как `denied`, а не как неудачный запрос

### Requirement: Частые повторы при отказе аутентификации не идут в API
Расширение ДОЛЖНО (SHALL) запоминать отказ класса «аутентификация» или «формат» вместе
со временем его наступления и не отправлять следующий запрос квоты автоматически (по таймеру
или по изменению файлов истории), пока с этого момента не пройдёт большее из времени жизни
кэша и пяти минут либо пока пауза не снята успешными данными. Неудачи повторяемых классов —
сетевые и сбои сервера провайдера — повторяются автоматически не чаще раза в пять минут,
независимо от времени жизни кэша и наличия кэша.

Без этого отвергнутый ключ не создаёт записи кэша, планировщик опроса считает отсутствие
кэша поводом обратиться к API, и расширение шлёт запрос на каждом тике таймера всё время,
пока ключ остаётся отвергнутым.

#### Scenario: Отвергнутый ключ не перезапрашивается каждый тик
- **WHEN** запрос квоты завершился отказом аутентификации, и автоматическое обновление
  наступает до истечения времени жизни кэша
- **THEN** запрос провайдеру не отправляется

#### Scenario: Малое время жизни кэша не укорачивает паузу
- **WHEN** время жизни кэша настроено на 60 секунд, запрос квоты завершился отказом
  аутентификации, и с тех пор прошло меньше пяти минут
- **THEN** автоматическое обновление запрос провайдеру не отправляет

#### Scenario: Подавление прекращается
- **WHEN** с момента записанного отказа аутентификации прошло большее из времени жизни кэша
  и пяти минут
- **THEN** ближайшее обновление, которое по правилам свежести кэша обращается к API,
  отправляет запрос

#### Scenario: Сетевой отказ повторяется не чаще раза в пять минут
- **WHEN** запрос квоты завершился по сетевой причине или сбою сервера провайдера, кэша нет,
  и автоматическое обновление наступает раньше чем через пять минут после неудачи
- **THEN** запрос провайдеру не отправляется

#### Scenario: Сетевой отказ не ждёт времени жизни кэша
- **WHEN** запрос квоты завершился по сетевой причине, время жизни кэша больше пяти минут,
  и с момента неудачи прошло пять минут
- **THEN** ближайшее обновление, которое по правилам свежести кэша обращается к API,
  отправляет запрос, не дожидаясь истечения времени жизни кэша

### Requirement: Отвергнутый ключ отличим от недоступности сервиса
Расширение ДОЛЖНО (SHALL) показывать отказ класса «аутентификация» отдельным состоянием,
называющим причиной учётные данные, отдельно от показа протухших или недоступных данных,
чтобы отказ, требующий действий пользователя, не выглядел так же, как отказ, который
пройдёт сам. Состояние невыполненного входа ДОЛЖНО (SHALL) показываться только тогда,
когда учётных данных нет.

#### Scenario: Отвергнутый ключ называется отвергнутым
- **WHEN** провайдер отвергает настроенный токен
- **THEN** расширение сообщает, что учётные данные отвергнуты

#### Scenario: Временная недоступность не выдаётся за проблему с ключом
- **WHEN** запрос квоты завершился по сетевой причине или сбою сервера провайдера
- **THEN** расширение показывает закэшированные или протухшие данные, а без кэша — режим
  затрат или отсутствие данных, не называя учётные данные и не сообщая, что вход
  не выполнен

#### Scenario: Провайдер без входа не называется невыполненным входом
- **WHEN** провайдер — Bedrock, API-ключ или сторонний адрес, либо запросы к API выключены
  пользователем, и нет ни кэша, ни локальных затрат
- **THEN** показывается отсутствие данных, а не «вход не выполнен»

#### Scenario: Отсутствие учётных данных называется невыполненным входом
- **WHEN** учётных данных провайдера нет, кэша нет, и локальных затрат нет
- **THEN** расширение сообщает, что вход не выполнен

## ADDED Requirements

### Requirement: Истёкший токен Anthropic не отправляется в API
Расширение ДОЛЖНО (SHALL) не отправлять запрос ограничений Anthropic, если срок действия
OAuth-токена, записанный рядом с ним, истёк или истекает в ближайшие 60 секунд, и в этом
случае не ставить опрос на паузу, не показывать состояние отвергнутых учётных данных
и сообщать, что токен истёк и его обновит любой запрос в Claude Code. Срок, не являющийся
правдоподобной отметкой времени в миллисекундах, считается отсутствующим.

#### Scenario: Истёкший токен не порождает запроса
- **WHEN** срок действия токена в учётных данных уже прошёл
- **THEN** запрос к API не отправляется, и в кэш ничего не пишется

#### Scenario: Токен, истекающий в пределах запаса, не отправляется
- **WHEN** срок действия токена истекает через 30 секунд
- **THEN** запрос к API не отправляется

#### Scenario: Токен с запасом отправляется
- **WHEN** срок действия токена истекает через 120 секунд
- **THEN** запрос к API отправляется

#### Scenario: Истёкший токен не выдаётся за отвергнутый вход
- **WHEN** опрос пропущен из-за истёкшего токена
- **THEN** показываются закэшированные, протухшие данные или режим затрат с пометкой
  об истёкшем токене в подсказке, а не состояние отвергнутых учётных данных

#### Scenario: Истёкший токен без данных не советует обновить
- **WHEN** опрос пропущен из-за истёкшего токена, кэша нет, и локальных затрат нет
- **THEN** метка сообщает, что вход истёк, без цвета ошибки, а не предлагает обновить данные

#### Scenario: Обновлённый токен подхватывается без ожидания паузы
- **WHEN** опрос был пропущен из-за истёкшего токена, после чего Claude Code записал
  новый токен
- **THEN** ближайшее обновление, которое по правилам свежести кэша обращается к API,
  отправляет запрос

#### Scenario: Неправдоподобный срок не останавливает опрос
- **WHEN** срок действия в учётных данных отсутствует, не является числом, меньше `1e12`
  или отстоит от текущего момента больше чем на год вперёд
- **THEN** запрос к API отправляется

#### Scenario: На macOS истёкший файл не заслоняет Keychain
- **WHEN** на macOS при пути учётных данных по умолчанию токен в файле истёк, а в Keychain
  лежит токен с более поздним сроком
- **THEN** запрос отправляется с токеном из Keychain

#### Scenario: Keychain не читается без опроса
- **WHEN** на macOS токен в файле истёк, а обновление не обращается к API (кэш свежий,
  пауза или определение провайдера)
- **THEN** Keychain не читается

### Requirement: Отказ учётных данных Anthropic распознаётся по статусу ответа
Расширение ДОЛЖНО (SHALL) считать ответ Anthropic со статусом 401 или 403 отказом класса
«аутентификация», даже если ответ несёт заголовки ограничений, и не выводить из такого
ответа данных об ограничениях.

#### Scenario: Отвергнутый токен даёт отказ аутентификации
- **WHEN** Anthropic отвечает статусом 401 без заголовков ограничений на неистёкший токен
- **THEN** запрос завершается отказом класса «аутентификация», и в кэш ничего не пишется

#### Scenario: Запрет доступа даёт отказ аутентификации
- **WHEN** Anthropic отвечает статусом 403
- **THEN** запрос завершается отказом класса «аутентификация»

#### Scenario: Заголовки не перевешивают отказ
- **WHEN** Anthropic отвечает статусом 401 или 403, и ответ несёт заголовки ограничений
- **THEN** запрос завершается отказом класса «аутентификация», а заголовки не разбираются

### Requirement: Сбой сервера Anthropic остаётся повторяемым
Расширение ДОЛЖНО (SHALL) считать ответ Anthropic со статусом 5xx неудачным запросом
повторяемого класса: без записи в кэш, без паузы опроса на время жизни кэша и без указания
на учётные данные.

#### Scenario: Ошибка сервера не ставит опрос на паузу на время жизни кэша
- **WHEN** Anthropic отвечает статусом 500 или 529
- **THEN** запрос завершается неудачей повторяемого класса, в кэш ничего не пишется,
  и учётные данные не называются

### Requirement: Ответ Anthropic без заголовков ограничений считается дрейфом формата
Расширение ДОЛЖНО (SHALL) считать ответ Anthropic, который не является отказом
аутентификации или сбоем сервера и не несёт ни одного из единых заголовков ограничений,
неудачным запросом класса «формат», чтобы такой ответ проявлялся как протухшие или
закэшированные данные, а не как нулевой расход.

#### Scenario: Успешный ответ без заголовков не даёт нулевого расхода
- **WHEN** Anthropic отвечает статусом 200 без единых заголовков ограничений
- **THEN** запрос завершается неудачей класса «формат», и «0 % использовано» не кэшируется

#### Scenario: Клиентская ошибка без заголовков тоже считается дрейфом формата
- **WHEN** Anthropic отвечает статусом 400 или 404 без единых заголовков ограничений
- **THEN** запрос завершается неудачей класса «формат»

#### Scenario: 429 без заголовков не повторяется каждый тик
- **WHEN** Anthropic отвечает статусом 429 без единых заголовков ограничений
- **THEN** запрос завершается неудачей класса «формат»

### Requirement: Неудача класса «формат» не обвиняет учётные данные
Расширение ДОЛЖНО (SHALL) после неудачи класса «формат» у любого провайдера не показывать
ни состояние отвергнутых учётных данных, ни состояние невыполненного входа.

#### Scenario: Дрейф формата с кэшем не выдаётся за проблему с ключом
- **WHEN** запрос квоты завершился неудачей класса «формат», и кэш есть
- **THEN** показываются закэшированные или протухшие данные, учётные данные не называются

#### Scenario: Дрейф формата без кэша не выдаётся за невыполненный вход
- **WHEN** запрос квоты завершился неудачей класса «формат», и кэша нет
- **THEN** показывается режим затрат или отсутствие данных, а не «вход не выполнен»

### Requirement: Ручное обновление обходит паузу опроса
Расширение ДОЛЖНО (SHALL) при ручном обновлении запрашивать квоту, даже если автоматический
опрос поставлен на паузу или отложен после повторяемой неудачи. Если межоконную блокировку
опроса держит другое окно, это окно запроса не отправляет, показывает текущее состояние
с учётом активной паузы, а результат соседнего окна подхватывает ближайшим обновлением.

#### Scenario: После повторного входа ручное обновление опрашивает сразу
- **WHEN** опрос на паузе после отказа аутентификации, и пользователь запускает ручное
  обновление
- **THEN** запрос провайдеру отправляется, и при успехе пауза снимается

#### Scenario: Ручное обновление при чужой блокировке не мигает
- **WHEN** опрос на паузе после отказа аутентификации, блокировку держит другое окно,
  и пользователь запускает ручное обновление
- **THEN** запрос не отправляется, и состояние отвергнутых учётных данных сохраняется

#### Scenario: Неудачное ручное обновление паузу не снимает
- **WHEN** ручное обновление во время паузы снова завершается отказом аутентификации
- **THEN** пауза остаётся в силе для автоматических обновлений

### Requirement: Пауза снимается свежими данными соседнего окна
Расширение ДОЛЖНО (SHALL) снимать паузу опроса, задержку повтора и пометку причины неудачи,
когда в общем кэше появилась запись того же провайдера, записанная позже момента неудачи,
и не показывать пометку причины, относящуюся к другому провайдеру.

#### Scenario: Успех другого окна снимает отказ
- **WHEN** окно запомнило отказ аутентификации, а другое окно затем успешно опросило того же
  провайдера и записало кэш
- **THEN** первое окно показывает данные из кэша без состояния отвергнутых учётных данных

#### Scenario: Более старый кэш отказ не снимает
- **WHEN** запись кэша того же провайдера сделана раньше момента отказа
- **THEN** пауза и состояние отвергнутых учётных данных сохраняются

#### Scenario: Смена провайдера убирает чужую пометку
- **WHEN** пометка об истёкшем токене Anthropic записана, после чего активным провайдером
  стал z.ai
- **THEN** пометка об истёкшем токене не показывается

### Requirement: Подсказки о входе верны для провайдера и причины
Расширение ДОЛЖНО (SHALL) называть способ исправления, подходящий провайдеру и причине:
для отвергнутого входа Anthropic (401 или статус неизвестен) — `claude auth login` и затем
ручное обновление под тем названием команды, которое показывает палитра на языке интерфейса; для запрета доступа Anthropic (403) — нейтральное
сообщение с кодом статуса без совета войти заново; для z.ai — проверку
`ANTHROPIC_AUTH_TOKEN` (или `ANTHROPIC_API_KEY`) в `~/.claude/settings.json`; при отсутствии
учётных данных — `claude auth login` для Anthropic, настройку `ANTHROPIC_AUTH_TOKEN` для z.ai,
а когда провайдер не определён — оба пути. Команда `claude login`, которой в Claude Code
нет, не предлагается нигде.

#### Scenario: Anthropic при 401 советует войти заново
- **WHEN** учётные данные Anthropic отвергнуты со статусом 401
- **THEN** подсказка предлагает выполнить `claude auth login`, затем ручное обновление,
  и не упоминает `ANTHROPIC_AUTH_TOKEN`

#### Scenario: Anthropic при 403 не советует входить
- **WHEN** Anthropic отказал в доступе со статусом 403
- **THEN** подсказка называет код 403 и не предлагает `claude auth login`

#### Scenario: z.ai советует проверить ключ
- **WHEN** учётные данные отвергнуты, а провайдер — z.ai
- **THEN** подсказка предлагает проверить `ANTHROPIC_AUTH_TOKEN` в `~/.claude/settings.json`

#### Scenario: Невыполненный вход называет рабочую команду для провайдера
- **WHEN** расширение показывает состояние невыполненного входа для Anthropic
- **THEN** подсказка содержит `claude auth login`

#### Scenario: Невыполненный вход z.ai не советует claude auth login
- **WHEN** расширение показывает состояние невыполненного входа для z.ai
- **THEN** подсказка называет `ANTHROPIC_AUTH_TOKEN` и не содержит `claude auth login`

#### Scenario: Неопределённый провайдер называет оба пути входа
- **WHEN** расширение показывает состояние невыполненного входа, а провайдер не определён
- **THEN** подсказка содержит и `claude auth login`, и `ANTHROPIC_AUTH_TOKEN`

#### Scenario: Отказ без известного статуса трактуется как отвергнутый вход
- **WHEN** состояние отвергнутых учётных данных Anthropic показывается без кода статуса
- **THEN** подсказка та же, что при статусе 401

#### Scenario: Название команды обновления совпадает с палитрой
- **WHEN** подсказка об отвергнутом входе показывается на английском, русском, японском
  или китайском
- **THEN** она называет команду обновления так же, как её показывает палитра команд
  на этом языке

### Requirement: Утилизация показывается только при живых данных об ограничениях
Расширение ДОЛЖНО (SHALL) использовать утилизацию и время сброса — в полосах и графике
дашборда, в прогнозе и в уведомлениях о порогах — только когда данные об ограничениях
получены из API или кэша, не считать их отсутствие сбросом окна и не выдавать нулевую утилизацию снимка без таких данных
за протухшие данные.

#### Scenario: Отвергнутый вход не рисует утилизацию
- **WHEN** дашборд получает данные в состоянии отвергнутых учётных данных
- **THEN** полосы утилизации и график прогноза не показываются, а строка состояния называет
  отвергнутые учётные данные

#### Scenario: Отвергнутый вход не шлёт уведомлений о порогах
- **WHEN** данные в состоянии отвергнутых учётных данных несут утилизацию из старого кэша
  выше порога
- **THEN** уведомление о пороге не показывается, и прогноз не опирается на эту утилизацию

#### Scenario: Переход к живым данным не выглядит как сброс окна
- **WHEN** после состояния без живых данных об ограничениях снова приходят живые данные
  о том же окне
- **THEN** ключи уже показанных уведомлений о порогах не сбрасываются, и повторного
  уведомления о том же пороге нет

#### Scenario: Истёкший токен назван на дашборде
- **WHEN** дашборд получает данные с пометкой истёкшего токена
- **THEN** строка состояния называет истёкший токен

#### Scenario: Снимок без живых данных не показывает ноль как протухшие данные
- **WHEN** при запуске загружается снимок состояния без данных об ограничениях
- **THEN** до первого обновления показывается состояние снимка, а не «0 %» с пометкой возраста

### Requirement: Сообщение об отказе Anthropic не раскрывает токен
Расширение ДОЛЖНО (SHALL) формировать сообщение о неудачном запросе Anthropic без OAuth-токена
и без тела ответа, называя только код статуса.

#### Scenario: Токен не попадает в сообщение
- **WHEN** запрос Anthropic завершается отказом аутентификации
- **THEN** сообщение неудачи содержит код статуса и не содержит токена
