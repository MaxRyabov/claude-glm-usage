## Context

`fetchRateLimitData` (`src/data/apiClient.ts`) шлёт POST на `/v1/messages` с OAuth-токеном
и сразу читает пять заголовков `anthropic-ratelimit-unified-*`. Статус ответа не проверяется.
Если заголовков нет, каждый `get` возвращает `null`, и результат собирается из умолчаний:
утилизация 0, сбросов нет, недельного окна нет, `allowed`. `DataManager` пишет это в кэш
с `dataSource: 'api'`.

Проба с заведомо фальшивым токеном (22.09.2026):

```
HTTP/1.1 401 Unauthorized
x-should-retry: false
{"type":"error","error":{"type":"authentication_error","message":"Invalid bearer token"}}
```

Заголовков ограничений в ответе нет. Протухший токен — ровно этот случай.

OAuth-токен Claude Code короткоживущий. В `~/.claude/.credentials.json` рядом с ним лежат
`expiresAt` (миллисекунды эпохи) и `refreshToken`: токен обновляет сам Claude Code, пока
запущен. Если Claude Code долго не запускали, в файле лежит истёкший токен. Это обычное
состояние, а не поломка.

Для z.ai то же самое закрыто изменением `support-zai-quota-formats` (в архиве). Там приняты
решения, на которые опирается этот дизайн: обнаружение отказа живёт в fetch, парсер тотален
(D5); отвергнутый ключ ставит опрос на паузу и называется вслух (D8). Инфраструктура паузы —
`PollBackoff` в `src/data/authBackoff.ts` — уже есть; её политика не меняется, добавляется
только чистый запрос момента записи (A7).

## Goals / Non-Goals

**Goals:**

- Ответ Anthropic без заголовков ограничений не становится закэшированными данными.
- Отказ учётных данных Anthropic даёт состояние `auth-rejected` и паузу опроса.
- Истёкший токен не отправляется в API и не выдаётся за отвергнутый вход.
- Подсказки верны для провайдера и указывают существующую команду: `claude auth login`
  для Anthropic, `ANTHROPIC_AUTH_TOKEN` для z.ai. Сбой сервиса не советует входить заново.
- Ни статус-бар, ни дашборд, ни прогноз, ни уведомления не выдают утилизацию за актуальную
  в состояниях без живых данных об ограничениях.
- Ни один класс неудачи не приводит к автоматическим запросам к API чаще раза в 5 минут
  при любой настройке TTL.
- Разбор заголовков, в том числе 429 с `denied`, не меняется; существующие тесты
  `anthropicRateLimit.test.ts` проходят без правок.

**Non-Goals:**

- Обновление OAuth-токена самим расширением. Токен принадлежит Claude Code, расширение его
  только читает.
- Разбор тела ответа. Статуса достаточно; тело всегда отменяется, но не читается.
- Общая для всех окон пауза опроса. Требует общего хранилища состояния; см. «Риски».
- Изменения схемы кэша и схемы снимка.
- Показ причины дрейфа формата («ответ провайдера не распознан»). Дрейф формата остаётся
  безмолвным, как у z.ai сейчас: кэш или протухшие данные. Вынесено в отдельный issue
  (решение пользователя: не раздувать patch).
- Журнал отказов (output channel). Отдельная задача.
- Отслеживание изменения файла учётных данных для снятия паузы. Keychain так не отследить,
  а ручное обновление и данные соседнего окна закрывают этот случай (A7).

## Decisions

### A1. Порядок классификации — учётные данные, срок токена, статус, наличие заголовков

1. **Чтение учётных данных.** Нет файла, нет токена, Keychain недоступен, путь из настройки
   вне `~/.claude` → `CredentialsUnavailableError` (A2), запроса нет. Файл есть, но не
   разбирается как JSON (например, читается в момент записи Claude Code) → обычный `Error`:
   повторяемый сбой, а не «вход не выполнен».
2. **Срок токена.** `expiresAt` считается сроком, только если это конечное число
   не меньше `1e12` (миллисекунды эпохи) и не дальше года вперёд; иначе срока нет, запрос
   отправляется, как сейчас. Если срок не позже чем через 60 с от текущего момента →
   `AnthropicTokenExpiredError`, запрос не отправляется (A5). Запас защищает от гонки
   «истёк в пути» и от небольшого расхождения часов; проверка правдоподобия — от смены
   единиц в формате файла, которая иначе навсегда остановила бы опрос.
3. **401 или 403** → `AnthropicAuthError` с кодом статуса. 401 — невалидный или протухший
   токен (проба). 403 бывает и по причинам, не связанным со входом (регион, политика
   организации, прокси), поэтому показывается нейтрально (A4), но паузу даёт так же:
   повтор через минуту ответит тем же.
4. **5xx** (включая 529 overloaded) → обычный `Error`: повторяемый сбой (A7).
5. **Есть хотя бы один из пяти заголовков** `anthropic-ratelimit-unified-5h-utilization`,
   `-7d-utilization`, `-5h-reset`, `-7d-reset`, `-5h-status` → разбор как сейчас, при любом
   статусе. Так 429 с `5h-status: denied` по-прежнему даёт `denied`. Иные заголовки
   с префиксом `anthropic-ratelimit-unified-` наличием данных не считаются: их нынешний
   разбор не читает, и засчитать их значило бы снова закэшировать 0 %.
6. **Иначе** → `AnthropicFormatError`. Сюда попадают 200 без заголовков, 4xx без них
   (например, 400/404, если модель `claude-haiku-4-5-20251001` снимут с поддержки) и 429
   без них.

Шаг 6 решил пользователь: повтор через минуту не поможет, значит пауза `'format'`, как
у z.ai для «успешного ответа без пригодных лимитов». 429 без единых заголовков — не
исчерпанная подписочная квота (её Anthropic сообщает заголовками), а частый повтор
только усугубит ограничение.

Почему статус раньше заголовков: 401 с заголовками на практике не встречается, но если
встретится, ответ всё равно значит «токен отвергнут», и доверять цифрам нельзя.

Почему наличие проверяется по пяти именам через `headers.get`, а не перебором всех
заголовков по префиксу: существующая тестовая заглушка `reply()` реализует только `get`.
Перебор потребовал бы править существующие тесты, а это запрещено критерием приёмки.

Тело ответа отменяется всегда, после чтения статуса и заголовков
(`response.body?.cancel()`, ошибки отмены глушатся): непрочитанное тело в `fetch` на undici
держит соединение до сборки мусора, и это касается успешного ответа в той же мере.

*Отвергнуто:* проверять только `response.ok`. Тогда 429 перестал бы давать `denied` — самое
важное состояние для пользователя на лимите.

### A2. Классы отказов

В `authBackoff.ts` (модуль остаётся без импортов) — базовые классы паузы
`CredentialRejectedError` и `QuotaFormatError` и функция
`backoffReasonOf(err): PollBackoffReason | null`:

- `ZaiAuthError extends CredentialRejectedError`, `ZaiFormatError extends QuotaFormatError`;
- `AnthropicAuthError extends CredentialRejectedError` (с полем `status: 401 | 403`),
  `AnthropicFormatError extends QuotaFormatError`.

В `apiClient.ts` — классы, которые паузы не дают:

- `AnthropicTokenExpiredError` — истёкший токен (A5);
- `CredentialsUnavailableError` — учётных данных нет (A1, шаг 1). Его бросают
  `readCredentials` и `DataManager.fetchZaiRateLimit`, когда не настроены URL или токен z.ai.
  Только этот класс даёт `no-credentials` после неудачного опроса (A6): иначе сбой сервиса
  без кэша выглядел бы как «вход не выполнен».

Зависимость идёт от `apiClient` к `authBackoff`, а не наоборот, поэтому цикла нет.

*Отвергнуто:* добавить в `DataManager` ещё ветки `instanceof Anthropic*` — третий провайдер
снова потребует правки классификатора. Отвергнуто и переименование `Zai*` в общие классы:
тесты `providerDetection.test.ts` проверяют `instanceof ZaiAuthError`.

### A3. Текст ошибки не несёт токена и тела ответа

Сообщение исключения содержит только статус, например `Anthropic rejected the OAuth token
(HTTP 401)`. Токен уходит заголовком запроса и в сообщение не попадает. Тело не читается.

### A4. Метки и подсказки ветвятся по провайдеру и причине

В Claude Code 2.1.220 подкоманды `claude login` нет: `claude --help` перечисляет `auth`,
вход — `claude auth login`. Строка `claude login` уже стоит в подсказке `no-credentials`
и в таблице провайдеров README; исправляется там же, причина одна.

| Состояние | Провайдер | Метка | Подсказка |
|---|---|---|---|
| `auth-rejected` | `z-ai` | `🤖 API key rejected` (без изменений) | прежний текст про `ANTHROPIC_AUTH_TOKEN` (без изменений) |
| `auth-rejected`, 401 или статус неизвестен | `claude-ai` | `🤖 Login rejected` | `Anthropic rejected your Claude Code login.\nRun: claude auth login, then "Claude+GLM: Refresh Now"` |
| `auth-rejected`, 403 | `claude-ai` | `🤖 Access refused` | `Anthropic refused access (HTTP 403).\nThis is not always a login problem: check region, organization policy or proxy.` |
| `no-credentials` | `claude-ai` | `🤖 Not logged in` (без изменений) | `Claude Code is not logged in.\nRun: claude auth login` |
| `no-credentials` | `z-ai` | `🤖 Not logged in` (без изменений) | `z.ai API key is not configured.\nSet ANTHROPIC_AUTH_TOKEN in ~/.claude/settings.json` |
| `no-credentials` | `unknown` и прочие | `🤖 Not logged in` (без изменений) | `Claude Code is not logged in.\nRun: claude auth login — or, for z.ai, set ANTHROPIC_AUTH_TOKEN in ~/.claude/settings.json` |

`unknown` — самый частый случай «вход не выполнен»: в режиме `auto` без OAuth-токена,
без настроек z.ai и без API-ключа `detectProvider` возвращает именно его. Поэтому подсказка
называет оба пути (решение пользователя): расширение обслуживает и Claude, и GLM.

Код статуса отказа доходит до статус-бара полем `ClaudeUsageData.rejectionStatus`; если
его нет (например, состояние восстановлено из снимка), показывается вариант 401.

Название команды обновления в подсказке 401 во всех языках — ровно `cmd.refresh`
из соответствующего `package.nls*.json`, включая английский: иначе пользователь не найдёт
её в палитре. Совпадение проверяется тестом для каждого языка. Вторая половина подсказки
нужна, потому что пауза снимается только успехом или истечением срока паузы (A7), а ручное
обновление её обходит.

`auth-rejected` у других провайдеров недостижимо: `DataManager` опрашивает API только для
`claude-ai` и `z-ai`. Если состояние всё же придёт от другого провайдера, показывается
вариант z.ai, как сейчас.

### A5. Истёкший токен — не отказ

`readCredentials` возвращает вместе с токеном `expiresAt`. Истёкший по A1 токен даёт
`AnthropicTokenExpiredError` без запроса к API:

- **паузы нет.** Проверка локальная, HTTP-запроса нет. Как только Claude Code обновит
  токен, ближайший опрос пройдёт.
- **Не красное и не `auth-rejected`.** Показывается кэш, протухшие данные или режим затрат,
  а подсказка статус-бара и подвал дашборда называют причину: `Claude Code login token
  expired — any Claude Code request refreshes it`. Метка с данными не меняется (решение
  пользователя: истёкший токен — нормальное состояние, шуметь не нужно). Когда показывать
  нечего (`no-data`), метка — приглушённое `🤖 Login expired` вместо `🤖 Claude: run refresh`:
  совет «обновите» здесь не помог бы.
- **macOS.** Откат на Keychain сейчас бывает только при ошибке чтения файла, а у Claude Code
  v2.x на macOS токен живёт в Keychain — старый файл может лежать с давно истёкшим сроком.
  Поэтому на darwin при пути по умолчанию, если токен из файла истёк, читается и Keychain,
  и берётся запись с бо́льшим сроком. Сравнение делается **только в `fetchRateLimitData`**,
  то есть после того как решено опрашивать: `readCredentials` вызывает и `detectProvider`
  на каждом обновлении каждого окна, и чтение Keychain там запускало бы `/usr/bin/security`
  раз в минуту бессрочно. Выбор — чистая функция с внедряемым чтением Keychain,
  тестируется без macOS.

Пометка причины хранится в `DataManager` полем `pollNotice: 'token-expired' | null` вместе
с провайдером, к которому она относится (A7).

*Отвергнуто:* считать 401 на истёкшем токене отказом. Пользователь, который просто давно
не открывал Claude Code, получил бы красное «Login rejected» и бесполезный совет.

### A6. Исход неудачи и состояние без опроса — чистые функции

Классификация из `catch` опроса выносится в новый модуль `src/data/pollOutcome.ts`.
Мешает тестировать её в `DataManager` не импорт `vscode` (`statusBar.ts` тоже его импортирует
и тестируется), а синглтон, читающий настоящий `~/.claude`; чистые функции этого не требуют.

```
pollFailureOutcome(err, { hasCache, cacheValid, hasCostData })
  → { backoff: PollBackoffReason | null, retryDelay: boolean,
      dataSource, notice, rejectionStatus }
```

| Причина | Пауза | С кэшем | Без кэша | Пометка |
|---|---|---|---|---|
| отказ учётных данных | A7 | `auth-rejected` | `auth-rejected` | — |
| формат | A7 | `cache` / `stale` | `local-only` / `no-data` | — |
| истёкший токен | нет | `cache` / `stale` | `local-only` / `no-data` | `token-expired` |
| учётных данных нет | нет | `cache` / `stale` | `local-only` / `no-credentials` | — |
| прочее (сеть, 5xx, JSON) | задержка 300 с (A7) | `cache` / `stale` | `local-only` / `no-data` | — |

До изменения любая неудача без кэша давала `no-credentials` («Not logged in»). Для сбоя
сервиса и дрейфа формата это ложный совет войти; теперь `no-credentials` после опроса даёт
только отсутствие учётных данных.

Ветка, где опроса нет вовсе (провайдер без данных об ограничениях или API выключен
пользователем, кэша нет), сейчас тоже даёт `no-credentials` без затрат — в том числе
у Bedrock и API-ключа, у которых вход не при чём. Её исход — `idleDataSource(provider,
hasCostData)`: `local-only` при затратах, иначе `no-credentials` только для `unknown`,
остальным `no-data`.

### A7. Решение об опросе — чистая функция `pollDecision`

Условие опроса из `DataManager.shouldCallApi` переезжает в `pollOutcome.ts`, чтобы сценарии
паузы проверялись табличным тестом. «Автоматическое обновление» ниже — и тик таймера
(60 с), и обновление от наблюдателя за JSONL (не чаще раза в 15 с при активности).

- **Ручное обновление** (`forceRefresh`) опрашивает всегда. Если межоконный замок держит
  другое окно, это окно запроса не шлёт и показывает текущий кэш; результат соседа
  подхватывается ближайшим обновлением. Ждать замок не стоит: до 30 с блокировки
  (`LOCK_STALE_MS`) ради одного показа.
- **Пауза `'credentials'` или `'format'`** — автоматического опроса нет, пока с момента
  отказа не пройдёт `max(TTL, 300 с)`. Нижняя граница нужна потому, что TTL настраивается
  от 60 с (`package.json`), а правило CLAUDE.md — не чаще раза в 5 минут в простое.
  `PollBackoff` не меняется: длительность ему передаёт вызывающий.
- **Повторяемый сбой** (сеть, 5xx, нечитаемый JSON учётных данных) — автоматический опрос
  не раньше чем через 300 с после него, независимо от TTL и наличия кэша. До изменения
  сеть без кэша повторялась на каждом автоматическом обновлении, а 5xx кэшировал ноль.
  Решение пользователя: повторяемый, но не чаще раза в 5 минут. Время хранится
  в `DataManager`: у этой задержки другой смысл, чем у паузы.
- **Иначе** — прежние правила: нет кэша → опрос; кэш протух → опрос, если JSONL обновлялся
  за 5 минут.

`pollDecision` возвращает `'poll' | 'skip' | 'poll-if-jsonl-recent'`. Последний исход
`DataManager` разрешает вызовом `wasJsonlUpdatedRecently`, как сейчас: этот вызов обходит
`stat` по всему дереву JSONL (на машине пользователя — сотни мегабайт), и вычислять его
заранее на каждом обновлении было бы дорого.

Пауза, задержка повтора и пометка причины снимаются успешным опросом этого окна **или**
появлением в кэше записи того же провайдера, более новой, чем момент неудачи: её записало
соседнее окно, которое опросило успешно. Для этого `PollBackoff` получает чистый запрос
`recordedAt(provider)`. Пометка причины относится к провайдеру и не показывается после
смены провайдера.

Все ветки, где этот вызов не опрашивает сам, — пропуск по решению, замок у соседа, свежий
кэш, найденный под замком, — получают `dataSource` из одной функции `noPollOutcome`
с учётом активной паузы и пометки. Сейчас ветки с замком возвращают голый `cache`/`stale`,
и при паузе метка мигала бы между «Login rejected» и обычными данными.

### A8. Где утилизация считается живой — одна функция

`showsRateData(providerType, dataSource)` (в `pollOutcome.ts`): провайдер `claude-ai`
или `z-ai` и `dataSource` ∈ {`api`, `cache`, `stale`}. Сейчас каждый потребитель решает
сам и исключает только `local-only`, поэтому в `auth-rejected` утилизация из старого кэша
всплывает везде. Потребители и чистые функции, через которые они тестируются:

- **дашборд** — экспортируемая `dashboardUsage(usage)` добавляет к данным `showRateData`;
  скрипт веб-представления использует его вместо собственного условия для полос и графика
  прогноза. В подвале — `(credentials rejected)` для `auth-rejected`,
  `(login token expired)` при пометке `token-expired`;
- **прогноз** — `getPrediction` не передаёт утилизацию в `computePrediction`, если
  `showsRateData` ложна;
- **уведомления** — `rateSignalsFor(data): RateLimitUsage | null` в `notificationDecision.ts`
  даёт `null` без живых данных; `checkAndNotify` тогда пропускает и
  `decideRateLimitNotifications`, и `checkWindowResets`. Иначе переход «нет данных → есть
  данные» выглядел бы как сброс окна, и ключи уведомлений обнулились бы — повторное
  «92 % used» о том же окне. Для действий условие строже: `actsOnRateData` пропускает
  только `api` и `cache`, без `stale`. Кэш пересчитывает остаток до сброса от абсолютного
  времени, а снимок при старте (тоже `stale`) хранит остаток на момент сохранения, и
  проверка смены окна запомнила бы конец окна, завышенный на возраст снимка (найдено
  ревью PR #12). Протухшие данные не меняются — на них уже отреагировали, пока они были
  свежими;
- **снимок при старте** — `snapshotDataSource(saved)`: `stale`, только если снимок нёс
  живые данные. Снимок из `local-only`, `no-data`, `no-credentials` или `auth-rejected`
  сохраняет своё состояние: иначе его нулевая утилизация показывалась бы как
  «5h: 0% [N ago]» до первого обновления — ровно симптом #8. Схема снимка не меняется:
  `dataSource` в нём уже хранится.

Проводка этих функций в `extension.ts`, `panel.ts` и `DataManager` — однострочные вызовы;
тестами покрываются сами функции.

## Risks / Trade-offs

- **Пауза живёт в памяти окна.** `apiLock` сериализует опросы, но не передаёт знание
  об отказе: окно B не знает, что окно A получило 401, и без кэша опросит само. N окон
  в простое дают до N запросов за паузу. У z.ai так с 1.2.0. → Принято; общая пауза —
  в Non-Goals.
- **401 на неистёкшем токене не всегда лечится входом** (например, политика Anthropic на
  токены вне Claude Code). → Совет в худшем случае бесполезен, но безвреден.
- **Ложный 401 при гонке с обновлением токена.** Если Claude Code отзывает старый токен при
  обновлении, окно, прочитавшее файл до записи, получит 401 и красное «Login rejected»
  (предположение о поведении Claude Code). → Принято: не дольше паузы, ручное обновление
  или успех соседнего окна его снимают.
- **Тарифы с иным набором заголовков.** Если Anthropic на части тарифов пришлёт только
  заголовки не из пяти проверяемых, исправный ответ станет дрейфом формата: безмолвная
  пауза, кэш или протухшие данные. → Нынешний разбор опирается ровно на эти пять, и,
  по комментариям в тестах, `5h-*` приходят на обоих известных тарифах (Pro, Max);
  живьём не перепроверялось. Показ причины дрейфа вынесен в отдельный issue.
- **Пропажа только части заголовков** (например, остался один `5h-status`) → разбор как сейчас:
  отсутствующие утилизации дают 0. → Принято: частичный ответ не порождается отказами, которые
  ловит это изменение.
- **Расхождение часов больше 60 с** → истёкший токен может уйти в запрос и получить 401 →
  `auth-rejected`. → Принято: редкий случай, не хуже нынешнего «0 %».
- **Холостые чтения учётных данных.** При истёкшем токене без кэша каждое автоматическое
  обновление читает файл (на macOS при истёкшем файле ещё и Keychain). HTTP-запросов нет.
  → Принято: локальная работа дешёвая; `detectProvider` Keychain не трогает.
- **Критерий #8 «повторяемыми, как сейчас».** Теперь «повторяемые» значит «без паузы
  на TTL, но не чаще раза в 5 минут». → Отметить в описании PR.

## Migration Plan

Миграции нет: схемы кэша, снимка и настройки не меняются. Кэш с нулём, записанный 1.2.0
при протухшем токене, остаётся в кэше. Пока он свежий, опроса нет. Когда он протухнет, опрос
пойдёт, только если JSONL обновлялся за последние 5 минут: в простое ноль виден как
«5h: 0% [N ago]» с пометкой возраста. При работающем Claude Code токен к этому моменту
обычно уже обновлён, и придут настоящие данные. Ручное обновление опрашивает сразу. Откат —
возврат к 1.2.0.
