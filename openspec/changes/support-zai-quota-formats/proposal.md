# Proposal: support-zai-quota-formats

## Why

У z.ai одновременно живут два поколения ответа о квоте. Новые кредитные тарифы отвечают
на `GET {origin}/api/monitor/usage/quota/limit` записями `CREDIT_LIMIT` с абсолютными
величинами кредитов, а прежние токенные тарифы продолжают присылать процентные
`TOKENS_LIMIT`. Наш парсер отбирает только `type === 'TOKENS_LIMIT'`, поэтому на новом
тарифе **все окна квоты отбрасываются и расширение показывает 0 %** — врут и статус-бар,
и шкалы дашборда, и уведомления о лимитах.

Проверка на двух живых учётных записях вскрыла второй, независимый дефект: отвергнутый
ключ z.ai возвращает **HTTP 200** и `{"success": false}`, а не 401. `fetchZaiQuota`
проверяет только `response.ok`, поэтому просроченный токен разбирается как исправная
простаивающая учётная запись, попадает в кэш с `dataSource: 'api'` и бессрочно
показывается как уверенные «0 % использовано».

| ID | Дефект |
|----|--------|
| QF-1 | Записи `CREDIT_LIMIT` отфильтровываются, поэтому на новых тарифах все окна показывают 0 %. |
| QF-2 | `zaiUnitToMs` считает `unit: 6` (недели) сутками, поэтому недельное окно без `nextResetTime` сообщает горизонт сброса в одни сутки вместо семи. Та же карта называет `unit: 5` минутами, хотя это месяцы; сейчас это замаскировано лишь тем, что `TIME_LIMIT` отсекается по типу, и маска спадёт ровно в тот момент, когда фильтр по типу расширится, — а QF-1 этого и требует. |
| QF-3 | Ответы без `unit`/`number` (форма до 2026-09) дают длину окна 0, поэтому недельное окно не опознаётся вовсе и `has7dLimit` остаётся ложным. |
| QF-4 | Отказ аутентификации приходит как HTTP 200 с `success: false` и разбирается как 0 % использовано, минуя всю лестницу деградации: кэш → протухшие данные → только затраты. |
| QF-5 | Повтор «Bearer → сырой токен» срабатывает по HTTP 401/403, которых живой API не возвращает, поэтому в реальной работе запасной вариант недостижим. |
| QF-6 | Новые тарифы сообщают абсолютные кредиты (использовано, лимит, остаток) и уровень тарифа, а расширение выбрасывает это целиком. |
| QF-7 | `cacheToRateLimitData` выводит `has7dLimit` из условия `reset7dAt > 0`, тогда как `writeCache` всегда пишет `now + resetIn7d` — около 1,8 × 10⁹. Поэтому любое чтение из кэша утверждает, что недельное окно есть, — для **всех** провайдеров, включая Anthropic Pro. |
| QF-8 | Полностью исчерпанное окно z.ai сообщает `allowed_warning`, но никогда `denied`, поэтому красное состояние статус-бара для z.ai недостижимо даже при 100 %. |

## What Changes

- **QF-1, QF-2, QF-3** → Заменить определение окон поэлементной утиной типизацией,
  портированной из эталонной реализации: классифицировать по паре `(type, unit)`, где она
  указана, и откатываться к позиции в массиве, где не указана. Глобального переключателя
  версии формата намеренно **нет**, поэтому наполовину мигрировавшие ответы деградируют
  поэлементно, а не целиком.
- **QF-4, QF-5** → Разбирать конверт `{code, msg, success, data}` до разбора квоты. Отказом
  считать только явный `success: false`, сопоставлять `code` со статусом и переключать
  перебор способов авторизации по классу отказа, а не по HTTP-статусу. Поле `msg`
  пользователю не показывать: z.ai отдаёт его то по-английски, то по-китайски, не считаясь
  с `Accept-Language`.
- **QF-6** → Донести до дашборда абсолютные величины кредитов и уровень тарифа
  необязательными полями.
- **QF-7** → Хранить `has7dLimit` в кэше явно, а не выводить.
- **QF-8** → Сообщать `denied`, когда окно исчерпано полностью.
- **Новое, вынужденное исправлением QF-4**: отказ по отвергнутому токену превращает
  закэшированный успех в исключение, а планировщик опроса обращается к API на каждом тике
  таймера, пока кэша нет. Поэтому изменение дополнительно запоминает отказы аутентификации
  и не повторяет запрос раньше, чем истечёт TTL кэша, а также показывает отдельное
  состояние «ключ отвергнут». Без этого исправление меняло бы неверное число на запрос
  каждые тридцать секунд — против правила проекта «не чаще одного обращения в пять минут
  в простое».
- `parseZaiQuota` остаётся тотальной функцией и не бросает исключений; `fetchZaiQuota`
  сохраняет контракт с исключением, который `DataManager` уже превращает в показ кэша,
  протухших данных или режима только затрат.
- **BREAKING (внутреннее)**: схема дискового кэша переходит на `version: 4`. Читатель v4
  по-прежнему принимает файл v3 и всегда пишет v4, поэтому окно со старой версией
  расширения не может зациклиться с обновлённым на взаимной инвалидации. Схема снапшота
  дашборда намеренно остаётся на `version: 1`: новые поля необязательны, действующий
  валидатор их принимает, а инвалидация снапшотов стоила бы каждому пользователю той самой
  мгновенной отрисовки при холодном старте, ради которой сделан `optimize-dashboard-loading`.

## Capabilities

### New Capabilities
- `zai-quota-parsing`: как ответ z.ai о квоте классифицируется, нормализуется и признаётся
  неудачным — оба поколения тарифов, кредитная и токенная модели, определение окон,
  горизонты сброса, отказы аутентификации и политика повторов, а также путь результата
  в кэш и на дашборд.

## Impact

- **Затронутые спеки**: `zai-quota-parsing` (новая). Дополняет, но не отменяет требование
  «z.ai quota display» в
  `openspec/changes/add-zai-provider-support/specs/provider-detection/spec.md`.
- **Затронутый код**: `src/data/apiClient.ts` (ядро), `src/data/dataManager.ts`,
  `src/data/cache.ts`, `src/statusBar.ts`, `src/webview/panel.ts`, бандлы l10n.
- **Новые тесты**: `src/test/suite/anthropicRateLimit.test.ts`; дополнения к
  `providerDetection.test.ts`, `cache.test.ts` и `panel.test.ts`.
- **Поверхность регрессии Anthropic**: схема кэша и вебвью общие для всех провайдеров,
  а `fetchRateLimitData` сегодня не покрыт тестами вовсе. Он получает инъектируемый
  `fetchImpl`, чтобы путь разбора заголовков Anthropic можно было проверить, а не
  утверждать его неизменность на словах.
- **Заметное пользователям**: на прежних тарифах z.ai появится недельная строка и недельные
  уведомления, которых раньше не было, — это и есть исправление QF-3, и его нужно указать
  в changelog. У пользователей Anthropic Pro исчезнет фантомная недельная строка (QF-7).
  Исчерпанное окно z.ai теперь красит статус-бар красным (QF-8). Отвергнутый ключ теперь
  называется отвергнутым, а не показывает нули.
- **Вне объёма**: месячный лимит MCP (`TIME_LIMIT`) классифицируется, чтобы его нельзя было
  принять за окно квоты, но в интерфейсе не показывается; прочие эндпоинты монитора
  не затрагиваются.
